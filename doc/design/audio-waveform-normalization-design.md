# 音频波形音量归一化设计

本文是音频波形特性的**增强能力**设计：跨播放器的音量归一化，使前端波形视觉幅度在不同播放器、不同播放音量下保持一致。它建立在 Phase 1 捕获管线之上（见 [audio-waveform-capture-design.md](audio-waveform-capture-design.md)），是一条独立、可关闭、可叠加的能力。设计之初默认关闭，现默认开启（`b613d73` 改模板、`a05bd83` 改内置默认值，见 §3.3）。

状态：已实施并合入 main（`bb3abe4`…`8ed57c9`，截至 `326e1cc`）；依赖的 Phase 1 捕获管线（原分支 `phase1-audio-waveform`，已删除）亦已合入。本文为设计记录，与代码分叉时以代码为准。

4.0 修订（#67 捕获起步时的增益过冲，#68 帧率可配置）写在 §2~§6 中，以「4.0 修订」或 issue 号标出，均已实施，待真机确认（§5.1 的真机项）。文中「现行」指 4.0 修订之前的实现。

## 1. 目标与非目标

**要解决的问题**：各播放器各自以不同音量播放，导致前端波形整体大小不一致——安静的播放器缩成一条线、响的顶满。希望无论各家实际音量如何，波形视觉幅度一致。

**目标**：
- 跨播放器的**整体响度**归一化，前端波形幅度一致。
- 全局开关 + per-player 开关覆盖。
- 可关闭（全局开关，各播放器可单独覆盖，§3.3）；对某播放器关闭时，其帧值与输入逐位相同，即 Phase 1 的出帧行为（§3.2）。默认开启。
- 捕获刚启动时波形即为正常电平，不出现增益过冲（4.0 修订，#67）。
- 归一化的响应速度以时间计，不随出帧帧率变化（4.0 修订，#68）。

**非目标（明确不做）**：
- **分频段归一化**（每频段各自拉到目标、压平频谱）。那会抹掉音乐的频谱性格与逐曲差异，是「频谱白化/多段压缩」的创意 EQ 效果，与「如实展示音乐」相悖。本特性只做**全频段（broadband）扁平增益**，保留频谱形状。
- **运行时 API**（直播中实时调参）。走 config，与 `offset`/`poll`/`idle-hide` 同款。运行时调参是额外面，Phase-2-if-ever。
- 精确 LUFS 响度计量。视觉一致不需要广播级响度标准。

## 2. 参考

- **phandasm/waveform**（OBS 频谱插件，优先参考）：其 `normalize_volume` 即本特性原型——用 ~1s 滚动 RMS 测输入响度，`volume_compensation = min(volume_target_dBFS − dbfs(input_rms), max_gain_dB)`，作为**单标量**在 dB 域加到所有频谱 bin（全频段、可正可负）。默认 target `-8 dBFS`、max_gain `30 dB`、默认关。其 floor/ceiling 是**显示映射**、与归一化无关。
- **Widdit/now-playing-service**：**不做**音量归一化（仅用进程音量判暂停）。非本特性参考。

4.0 修订所依据的出处（2026-10-09 读取）：

- **phandasm/waveform 的起步状态不可取**：其 1 秒缓冲在 `update()` 中清零，`update_input_rms()` 恒按整个缓冲长度求均值；缓冲填满之前均值偏低、补偿偏高，没有专门处理（`src/source.cpp`、`src/source_generic.cpp`）。#67 与此同类。
- **ITU-R BS.1770-5** 附件 1（式 3~7，<https://www.itu.int/rec/R-REC-BS.1770>）：响度按 400 ms、重叠 75% 的门限块统计，块长按样本数取整；低于绝对门限 −70 LKFS 的块不计入均值，相对门限取绝对门限后均值之下 10 LU。本特性只取「静音不计入均值」的绝对门限，不做相对门限与 K 加权（§1 非目标）。
- **WebRTC AGC2**（`modules/audio_processing/agc2/`，据 GitHub 镜像 `webrtc-mirror/webrtc` 的 main 分支）：`speech_level_estimator_impl.cc` 的 `Update` 在累计语音时长未满 `kLevelEstimatorTimeToConfidenceMs`（400 ms）时泄漏系数取 1，即累计加权平均，其后才取 `kLevelEstimatorLeakFactor` 做指数遗忘；语音概率低于 `kVadConfidenceThreshold` 的帧不更新估计。`fixed_digital_level_estimator.cc` 的包络为瞬时起音（`kAttackFilterConstant = 0`）、慢释放，释放系数由释放时间与子帧时长换算（`kDecayFilterConstant` 的注释）。前者是 §3.2 起步期做法的出处，后者是升降不对称平滑的例子。
- **Web Audio API** `AudioParam.setTargetAtTime`（<https://webaudio.github.io/web-audio-api/>）：`v(t) = V1 + (V0 − V1)·e^(−(t−T0)/τ)`，`τ` 为阶跃响应到达 1 − 1/e 所需的时间。按帧间隔采样即得 §3.2 的每帧系数。

## 3. 设计

### 3.1 落点：后端烘焙

归一化在 **helper 的捕获循环内**完成，直接作用到帧的 `RMS` 与 `Bins`；前端拿到即一致幅度、零改动。

理由：归一化是**跨播放器**的，helper（知道每家样本、预热期已在测量每家）是 root 切歌时唯一能拿到**已收敛**增益的地方；纯前端在 root 场景下收不到非活跃家的帧、无法预先测其响度，架构上做不动。扁平增益不改频谱形状，前端既有的频率滤波照常工作。

### 3.2 算法：每家独立的 EMA-AGC

每路捕获维护独立的响度估计与增益：

1. **能量 EMA**（每家一个 `float`）：每帧 `ms = rms²`，按系数并入 `ema_ms`，响度估计 `rms_est = sqrt(ema_ms)`。
   - 现行实现：首帧播种 `ema_ms = ms`，其后 `ema_ms = α·ms + (1−α)·ema_ms`，`α = 0.03` 按帧定（`normAlpha`）。实际出帧约 25 帧每秒（§3.6），折合时间常数 1.31 s。
   - 4.0 修订：每帧带着它新增的非静音样本数 d（§3.6；整帧时 d = `hop`，残帧更少）进入归一化，系数与起步期都按时长计。**时长一律以样本数为单位**：时间常数折合 `N = τ × 采样率` 个样本（τ = 1.3 s，48000 Hz 下 N = 62400）；状态除 `ema_ms` 外增加两个累计样本数，本次起步以来计入的 t 与捕获开始以来计入的 T，凡期限都与 N 比。
     - **系数由时间常数换算**（#68）：`α(d) = 1 − e^(−d/N)`，升降同值，每帧按自己的 d 现算。`hop < fftSize` 时 RMS 的分析窗含上一帧的样本，权重仍按本帧新增的 d。
     - **静音门限**（#67）：`rms` 低于 −70 dBFS 的帧不并入 `ema_ms`、不计入 t 与 T，增益仍按当前 `ema_ms` 施加；尚无帧计入时增益为 1。`rms` 为非有限值的帧沿用现行处理，同样不并入、不计入。
     - **起步期**（#67）：`t < N` 时为起步期，期内依次做三件事：
       1. **重新起步**：`T < N` 且本帧功率超过 `ema_ms` 的 10 倍（高 10 dB 以上）时，此前计入的帧视为前导而丢弃，以本帧播种（`ema_ms = ms`，`t = d`）。只在捕获开始后计入的头 N 个样本（τ 秒音频）内允许，所以起步期保护最长持续到 2τ。
       2. **累计平均**：否则 `t += d`，再以系数 `max(α(d), d/t)` 并入。期内 `ema_ms` 等于已计入各帧功率按样本数加权的平均，首帧不再独占权重。
       3. **下限**：并入后若 `ema_ms` 低于本帧功率的一半，抬到一半并写回。于是期内任何一帧的输出都不高于目标 3.01 dB，期满时估计也不会落后最近的响帧 3 dB 以上。
     - `t ≥ N` 即起步期结束（25 帧每秒下是第 33 个整帧之后：32 帧为 61440 个样本，仍在期内），此后只做 `ema_ms += α(d)·(ms − ema_ms)`，即现行的对称指数平均。交接处不重算估计；`d/t` 在 `t = N` 时与 `α(d)` 相差不到 3%，系数也近于连续。
   - *ponytail：这是对 waveform「1s 样本环形缓冲精确 RMS」的简化——一个 float、无环形缓冲，对驱动一条缓慢增益足够平滑。*
2. **增益**：`gain_dB = min(target_dBFS − dbfs(rms_est), max_gain_dB)`，其中 `dbfs(x) = 20·log10(max(x, ε))`，`ε≈1e-10`（≈−200 dBFS，照 waveform 的 `DB_MIN`，防 `log10(0)` 下溢）。
   - 可正可负：响的播放器（`rms_est > target`）→ 负增益**衰减到目标**；只封上限 `max_gain`、不设下限。
   - 真静音 `rms_est→0` → `gain_dB = max_gain`，而 `max_gain × 近静音 ≈ 0`，**不会把静音放大成满屏**。
3. **作用**：`g = 10^(gain_dB/20)`，乘到帧的 `RMS` 与**所有 bins**（走带器用 RMS、频谱用 bins，须一致）。**全频段扁平增益**，频谱形状不变。

关闭时（`norm=0`）：helper **完全跳过** EMA 与增益、原样出帧 = Phase 1 当前行为，零开销零变化。

保活零帧（本帧窗口内没有非静音样本）不经归一化、不更新估计，修订前后相同；静音门限把同一原则延伸到未带静音标志而数值近零的帧。同一路捕获内切歌、暂停后恢复时起步期早已结束，估计延续；这两种情形下修订与现行的差别只有两点：25 帧每秒时系数由 0.03 变为 0.0303，低于 −70 dBFS 的帧不再把估计拉低。

#### 捕获起步的过冲（#67）

**现象**（2026-10-09 真机，`/audio-ws` 检查页）：某一路捕获重新启动时（活跃播放器在两家之间切换、活跃播放器被清除后重新开播、播放中途首个客户端连入、唯一的客户端断开后重连），RMS 走带开头是一段满幅，随后缓慢降到正常。同一路捕获内切歌、短暂停后恢复不出现。

**机制**：现行实现以首帧播种，到第 n 帧时首帧在 `ema_ms` 中的权重仍有 0.97^(n−1)。首帧若明显低于其后的电平，估计偏低、增益偏高，要等估计按 1.31 s 的时间常数追上才回落。每路捕获各建一个 `Normalizer`，所以只在捕获重新启动时出现。

**离线核对**：给仓库现有的 `Normalizer` 喂合成帧（target −14、max-gain 30），首帧取不同电平，其后恒为 −20 dBFS（下称正常帧），帧序号自首个正常帧起算，按 25 帧每秒折算时间。检查页走带画的是 `min(1, rms × 2.5)`，`rms ≥ 0.4`（高于目标 6.0 dB）即满幅。

| 首帧 | 首个正常帧高于目标 | 走带满幅帧数 | 回到目标 ±1 dB |
|---|---|---|---|
| 0，或 −80 dBFS | +15.2 dB | 9 | 第 52 帧（2.1 s） |
| −50 dBFS | +15.1 dB | 9 | 第 52 帧 |
| −34 dBFS（低 14 dB） | +11.6 dB | 8 | 第 51 帧 |
| −26 dBFS（低 6 dB） | +5.6 dB | 0 | 第 43 帧（1.7 s） |
| −20 dBFS（与其后相同） | 0 | 0 | 第 1 帧 |

其后的电平换成 −10 dBFS 结果相同，换成 −30 dBFS 时首个正常帧受 max-gain 封顶为 +14.0 dB，其余相同。曲线形态与真机报告一致：约 0.36 s 满幅，约 2 s 回到正常。首帧与其后电平相同时没有过冲。

**尚未核实**：真机上捕获刚启动时首个进入归一化的帧是否确实偏低，以及偏低的是恰为零的数据、很短的渐入还是别的形态，没有抓过帧。从代码看，起步增益只取决于 `ema_ms`，`ema_ms` 只来自进入 `Normalizer.Apply` 的帧，而分帧与 RMS 计算不会压低短帧（RMS 只对实际样本求均值）；所以满幅块若出自归一化，起步帧必然偏低，且偏低出自捕获到的数据本身。核实办法见 §5.1 的真机项。

多帧的低电平前导与渐入不是理论情形：活跃播放器被清除后重新开播、从另一家切过来这两种，捕获重启的时刻正是播放器开始出声的时刻，播放器自带的淡入（零点几秒到一秒）就是多帧渐入。另外，首帧恰好落在拍间的弱帧上时，不需要任何前导也会过冲（见下表「无前导」一行）。

**限度**：

- 前导比起步期保护（至多 2τ）还长时不在保护之内，例如 60 帧 −40 dBFS 之后才出声，表现同稳态下的大幅阶跃（+14 dB）。
- 首帧远高于其后（如启动瞬间的爆音）时估计偏高，按累计平均回落，比现行快，但仍要数秒。未见这类报告，不处理。

#### 取值与依据（4.0 修订）

- **τ = 1.3 s，升降同值**：现行 `α = 0.03` 在实际约 25 帧每秒下即 1.31 s，取整以保持稳态观感。换算后 25 帧每秒整帧的系数为 0.0303，时间常数相差 1%，差别在大幅阶跃的尾段最明显：两个系数的逐帧输出在合成节拍包络上相差不超过 0.006 dB，+10 dB 上阶跃 0.027 dB，−10 dB 下阶跃 0.048 dB。
- **起步期长 τ**：`max(α(d), d/t)` 在 `t = N` 处与指数平均自然衔接，不必另设长度。按累计样本数而不按帧数计，与帧率、残帧无关。累计平均到指数平均的切换同 WebRTC AGC2 的电平估计（§2）。
- **下限取本帧功率的一半（3.01 dB）**：恰是两帧累计平均的最坏情形（一帧极低、一帧正常，估计为正常帧的一半），取这个值不会让任何原本不过冲的序列变差；检查页走带在目标 −14 时要高出 6.0 dB 才满幅，留有 3 dB 余量。取 4、5 dB 时代价略小（落差 14 dB 时平均偏差 −2.0、−1.6 dB），允许的起步过冲相应变大。
- **重新起步取 10 dB**：合成包络上最响的帧比平均功率高 4.9~7.9 dB，10 dB 留有余量，音乐自身的拍点不触发。取 6 dB 时拍间落差大的音乐在头 τ 秒内每拍都重新起步，估计随拍起落。只有下限而没有重新起步时，长前导会把起步期耗尽：30 帧低 20 dB 的前导之后接节拍包络，新增满幅帧 3 / 6 / 11。
- **门限 −70 dBFS**：取 BS.1770 绝对门限的数值（此处是未加权的帧 RMS，单位不同）。max-gain 取默认 30 dB 时，这样的帧放大后仍低于 −40 dBFS，在波形上不可见；修订只是让它们不参与估计。
- **尚无帧计入时增益为 1**：此时没有可用的电平信息，而这些帧低于门限，放大与否在显示上没有差别。

#### 放弃的备选（4.0 修订）

- **以目标电平播种（初始增益 0 dB）**：电平偏离目标的播放器一起步就偏。原型结果：电平 −34 dBFS 的播放器首帧低于目标 19.9 dB，7.8 s 后才进入 ±1 dB；−20 dBFS 的首帧低 5.9 dB，3.2 s。把目标电平当作一帧先验并入累计平均同理。max-gain 默认 30 dB 正是为安静的播放器而设，这类播放器是常态，不取。
- **升快降慢**（本帧功率高于估计时改用短时间常数，原型取 60 ms）：各种前导之后都能在 3 帧内收敛，但稳态随之改变，估计跟随的是最响的帧而不是平均功率。在合成节拍包络（拍间落差 6、10、14 dB）上，稳态输出的功率平均降低 2.7、4.0、5.1 dB，最响帧相对目标由 +4.9、+6.6、+7.9 dB 降到 +1.3、+1.6、+1.7 dB：波形整体变小，节拍起伏被压平，现有 target 的取值也要重调。与「同一路捕获内不改变观感」冲突，不取。
- **只做累计平均与静音门限**（本文上一版）：高于门限的多帧前导之后仍有满幅帧，8 帧 −60 dBFS 之后 +9.5 dB、2 帧，20 帧每帧 +3 dB 的渐入 +9.3 dB、8 帧。不满足 #67。
- **起步期输出封顶而不写回估计**：期内各帧不超过目标 +3 dB，但估计仍被前导拉低，期满撤掉封顶时鼓起：30 帧 −40 dBFS 之后 +8.1 dB、4 帧满幅，30 帧每帧 +1 dB 的渐入 +5.9 dB。
- **起步期相对门限**（缓存期内各帧，估计取不低于期内最大帧功率 −10 dB 的各帧平均，BS.1770 相对门限的思路）：比正常低 10 dB 以上的前导在第一个正常帧到来时即被排除，过冲为 0；但比最大帧低不到 10 dB 的前导仍全部计入（20 帧低 9 dB 之后 +7.8 dB，须再加输出封顶），音乐里的弱帧也被排除而使估计偏高（落差 10、14 dB 时起步期平均偏差 −1.5、−3.3 dB，3.4、6.0 s 后才回到 ±1 dB），还要缓存并逐帧重算。门限相对均值而不是最大帧时偏差小，但低 10 dB 以内的长前导到期满仍未排除（32 帧低 10 dB 之后 +7.5 dB、3 帧满幅）。
- **下限生效时把累计权重折成一帧**：前导之后 3 帧内收敛，但有节拍的音乐里每个拍点都折一次，起步期内估计随拍起落。

### 3.3 配置（走 config，套 offset/poll/idle-hide 覆盖模式）

**全局**（yaml 字段 + CLI flag）：

| 键 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `audio-normalize` | bool | `true` | 全局开关（设计之初为 `false`，后改为默认开启） |
| `audio-normalize-target` | int | `-14` | 目标响度（dBFS） |
| `audio-normalize-max-gain` | int | `30` | 增益上限（dB） |
| `audio-frame-rate` | int | `25` | 音频帧的出帧帧率（帧每秒），范围 [15, 60]（4.0 修订，#68） |

**per-player 覆盖**（`*bool`，nil=跟随全局，套 `IdleHide *int` 模式）：

| 键 | 类型 | 含义 |
|---|---|---|
| `<player>-audio-normalize` | *bool | 该家开关覆盖；不设=跟随全局 |

**仅开关可 per-player 覆盖**，`target`/`max-gain` 保持全局：归一化的目的是拉到**共同目标**，target 本质全局；per-player 改 target 等于故意让某家更响/更轻、反破坏一致性，罕见。YAGNI：真有某家需单独调 target，再按同模式补 `<player>-audio-normalize-target`（几行）。

**解析器**：`GetPlayerAudioNormalize(name) bool`（套 `GetPlayerIdleHide`），命中 per-player 覆盖优先、否则回退全局。`target`/`max-gain` 经 `clampPolls` 同款钳制到合理区间（target 建议 [−60, 0]、max-gain [0, 45]，与 waveform 滑块一致）；per-player 覆盖只有开关，不参与钳制。

默认值 `target −14 / max-gain 30` 为起手值，具体填多少让波形填充好看由真机视觉实测决定。

**`audio-frame-rate`（4.0 修订，#68）**只有全局键与同名命令行参数 `-audio-frame-rate`，不设按播放器的覆盖（理由见 §3.6）：

- 默认 25：等于现状的实际帧率，升级后观感与数据量不变。
- 下限 15：帧间隔 66.7 ms，低于 `Capturer.Read` 的 100 ms 超时并留有余量。没有数据时每次超时返回都已满一个帧间隔，保活节拍维持约 100 ms；有数据时按样本数出帧的间隔（至多 70 ms）低于墙钟上限 100 ms，正常的连续流不会被墙钟切出残帧（§3.6）。
- 上限 60：直播画面常见的最高帧率，再高对显示没有增益。每帧约 2.1 KB，60 帧每秒时每个订阅约 126 KB/s（25 帧每秒时约 52 KB/s）。
- 越界（含 0 与负数）由 `clampAudioFrameRate` 钳到最近的边界并告警，在 `Load()` 返回前调用；边界为常量 `audioFrameRateMin` / `audioFrameRateMax`。钳制前的原值经 `noteWritten` 记下：`/service-status` 的 `config` 回显写下的值，`config_effective` 回显钳制后的值。
- config.yml 中写成非整数（字符串、小数、布尔）时告警并忽略该键，沿用默认值；命令行传入非整数由 `flag` 包拒绝，与现有整数参数相同。
- 落点按 `AGENTS.md` §3.3 的清单：`Config.AudioFrameRate`、`mergeYAML` 分支、模板与 `DefaultConfig()`、命令行参数（进 `globalFlags`）与 `flag.Visit`、钳制、`buildConfigEcho`、启动横幅、`doc/openapi.yaml`、`doc/API_RESPONSE_EXAMPLES.md`、`README.md`、仓库根 `config.yml`。

### 3.4 下发链路：控制协议扩展

main 单一真源持有 config，manager reconcile 时解析每家参数、经 capture 控制命令下发；helper 不读 config。

- 现 `capture <pid> <player>` → 扩成 `capture <pid> <player> <norm:0|1> <target_dbfs:int> <maxgain_db:int>`。
- main 侧总是带上三个参数（`norm = GetPlayerAudioNormalize(player)`，target/maxgain 取全局；`norm=0` 时 target/maxgain 占位、helper 忽略）。
- helper/main 是**同一个 exe**（manager spawn 同版本），无跨版本兼容问题——直接改成 6 字段；`parseControl` 对 capture 解析 6 字段、字段数不符按现有逻辑报坏命令丢弃。`stop <player>` 不变。
- 4.0 修订（#68）：capture 命令末尾加帧率，成为 `capture <pid> <player> <norm:0|1> <target_dbfs:int> <maxgain_db:int> <fps:int>`。帧率是全局值，main 把 `cfg.AudioFrameRate` 交给 manager，`applyControls` 拼进每条 capture 命令；归一化参数仍逐家解析。兼容性同上一条：`parseControl` 只认 7 个字段，6 个字段的旧格式按坏命令丢弃。范围钳制只在 config 层做，`parseControl` 只另外拒绝小于 1 的帧率（无法算出每帧样本数），不重复范围判断。

### 3.5 契约影响

- 归一化**开启**时，帧的 `RMS` 与 `bins` 为**已归一化**值，且可能 **>1**（响处被抬）。后端**不钳、保留信息**；消费者显示时自行 clamp（检查页本就 `min(1,…)`）。
- `openapi.yaml` 的 `/audio-ws`、`/{player}/audio-ws` 描述须注明：归一化开启时 RMS/bins 为归一化值、可能 >1。
- 帧**线格式不变**（仍 `…|rms|…|bins`），只是数值语义随归一化开关变化。epoch/player/ts 语义不变。
- 4.0 修订：线格式仍不变，检查页与前端的解帧不必改。出帧帧率由 `audio-frame-rate` 决定，`openapi.yaml` 中帧节拍的说明改为引用该配置；没有数据时静音帧约每 100 ms 一帧、空闲帧每 100 ms 一帧，均不变。帧率高于 46 时 `rms` 与 `bins` 的分析窗含上一帧的样本（§3.6），`openapi.yaml` 中这两个字段的说明同改。归一化开启的路在尚无帧计入估计时增益为 1（§3.2），`flags` bit0 照常置位。

### 3.6 出帧：按样本数分帧（4.0 修订，#68）

**现状**：`captureLoop` 以墙钟节拍 `cadence = 1s / 30` 出帧，但只在每次 `Capturer.Read` 返回后才检查是否到点，下一拍又从实际出帧的时刻起算。`Read` 由 WASAPI 事件驱动、约每 10 ms 返回一个包，33.3 ms 被量化成 40 ms，实际约 25 帧每秒。帧率做成可配后若沿用这一写法，30 实得 25，60 实得 50。

**修订**：

- 每帧的采样帧数 `hop = 采样率 / 帧率`（整数除法；48000 Hz 下 25 → 1920，30 → 1600，60 → 800）。读到的每个包（含带静音标志的包）按采样帧数计入，凑满 `hop` 即出一帧；包跨越帧界时在界上切开，前一段归本帧，后一段归下一帧。帧率由数据自身的时钟决定，与 `Read` 的返回粒度无关。帧率不能整除采样率时实际帧率为 `采样率 / hop`，比配置值高不到 0.13%。
- 带静音标志的包只推进计数、不进入窗口（不进入窗口是现状）。一帧内没有非静音样本即为保活零帧，节拍与帧率相同。
- 墙钟兜底：每次 `Read` 返回后都检查距上次出帧的时长，本次读到了数据时上限为 100 ms（`Read` 的超时），没读到数据时上限为一个帧间隔。到了上限而未凑满 `hop` 就出一帧，窗口内有不足一帧的非静音残余则作为真帧（残帧）发出，否则为保活零帧，计数归零。连续的数据流下按样本数先触发，不受影响。完全没有数据时 `Read` 每约 100 ms 超时返回一次，每次都已满一个帧间隔，保活节拍约 100 ms，与现状相同；数据断续到来（每次都读到少量样本、始终凑不满 `hop`）时由 100 ms 的上限兜住，两帧的间隔不超过上限加一个包的到达间隔。`hangThreshold` 与 `noCaptureAfter`（`audiocap/manager/gating.go`）所依赖的「捕获正常时最长约 100 ms 出一帧」因此不变。没读到数据时不直接用 100 ms，是因为超时返回可能略早于 100 ms（推断，未实测），那样保活会隔一次才发。
- 每帧连同它新增的非静音样本数一起交给归一化，作为该帧的时长权重（§3.2）；残帧的权重因此小于整帧。
- `rms` 与 `bins` 取最近至多 `fftSize`（1024）个非静音样本，`peak` 取本帧新增的全部非静音样本。`hop ≥ fftSize`（帧率不高于 46）时出帧后清空窗口，与现状相同；`hop < fftSize` 时窗口留着最近至多 `fftSize` 个非静音样本，每帧交给分析的是其中最近的 `fftSize` 个，出过保活零帧即清空，静音之前的样本不进入之后的帧。不这样做，帧率在 47 以上时每帧不足 1024 个样本，`Analyzer.Analyze` 只用到 Hann 窗的前一段，频谱泄漏变大、读数偏低。留的不是 `fftSize − hop` 个：静音包推进帧的计数而不新增样本，一帧新增的可以远少于 `hop`（60 帧每秒下一帧只新增 320 个时，`fftSize − hop` 的 224 个加上它只有 544 个，直流频点的读数从 0.5 掉到 0.28，而 RMS 不变）。
- 时间戳仍取编码时刻的 QPC。包以 10 ms 为粒度到达，帧界落在包内时该帧随这个包发出：30 帧每秒下帧间隔按 30、30、40 ms 交替，平均 33.3 ms；25 帧每秒恰为 4 个包，间隔均匀。
- 分帧与出帧循环（计数、切包、保留分析窗、墙钟兜底）做成不依赖平台的纯逻辑（`framer`、`clockDue`、`pumpFrames`），与 `window` 同放 `helper.go`，读包函数与时钟可注入；`captureLoop` 在激活成功后把 `Capturer.Read` 与 `time.Now` 交给它。

**放弃的备选**：

- 保留墙钟节拍，把下一拍改为从上一拍的理论时刻累加：平均帧率能对上，但每帧含多少样本随调度抖动（3 或 4 个包），线程停顿之后还要处理追帧；逻辑依赖时钟，离线测试须注入假时钟。按样本数分帧的结果只取决于样本流。
- 缩短 `Read` 的超时，或改成一次读空全部包：改动落在 `audiocap/wasapi` 的 COM 调用路径上，而量化出在出帧判断，不在读包。
- 帧率作为 helper 进程的启动参数：现有参数都随 capture 命令下发，沿用同一条路，不给 helper 的入口短路增加参数解析。
- 按播放器覆盖帧率：根端点在播放器之间切换时帧率会跳变，消费者的走带速度随之变化，不做。
- 上限定在 46 以内以免引入跨帧的分析窗：#68 以 60 为例，不取。

## 4. §0 与安全

- **关闭时零行为变化**：按播放器的最终取值判断（§3.3）——专属开关为 `false`，或未写专属开关且全局 `audio-normalize: false` 时，helper 对该播放器跳过估计与增益、原样出帧，即 Phase 1 的捕获链；专属开关为 `true` 的播放器在全局为 `false` 时仍归一化。默认开启，config.yml 未写该键即为开启。
- 全部在 helper 侧、纯算术（EMA + log/pow + 乘法），**无新 goroutine、无锁、无阻塞主线、不碰 RME 更多**。
- 增益数学有界（`max(x,ε)` 防下溢、`min(…,max_gain)` 封顶），无 NaN/Inf 外泄。
- helper 仍是隔离子进程：归一化若有 bug，最坏是波形数值异常（可降级能力），经 Phase 1 既有的坏帧降级/本地 recover 隔离，**不拖垮歌词/特效主线**（§0）。
- `config`/`logger` 的归一化字段须保持 `GOOS=linux` 可构建（§0.3）；helper 侧应用代码在 windows 捕获路径内，不影响 linux 构建面。
- 4.0 修订不改变上述边界：分帧与归一化仍全部在 helper 内，纯算术，无新 goroutine、无锁；`audio-frame-rate` 是纯标量，`config` 保持 `GOOS=linux` 可构建。帧率取上限 60 时每路每秒的 FFT 次数是默认值的 2.4 倍。`audiocap/wasapi` 只订正一处注释（读包超时的说明里不再提 cadence），代码不变，对声卡驱动的调用方式与频度不变。

## 5. 测试

**纯逻辑（CI 可测，无平台依赖）**——归一化增益数学抽为纯函数 + 一个 `Normalizer` 持状态结构，置于 helper 包无平台依赖处（如 `helper.go`，与 `parseControl`/`downmix` 并列，CI 可测；import dsp 纯包、不碰 windows），测：
- `dbfs` 下溢：`dbfs(0) == dbfs(ε)`、不产 Inf/NaN。
- 增益封顶：极安静输入 → `gain_dB == max_gain`。
- 衰减方向：输入响于 target → `gain_dB < 0`。
- EMA 播种：首帧 `rms_est == 首帧 rms`（无 0 冷启动过冲）；多帧收敛趋向稳态输入。
- 关闭路径：`norm=0` → 帧值与输入逐位相同（passthrough）。
- bins>1：响输入 + 高增益 → 存在 bin >1（确认后端不钳）。

**config**：`GetPlayerAudioNormalize` 的 per-player 覆盖优先/回退全局；target/max-gain 钳制（仅全局）。

**控制协议**：`parseControl` 解析 6 字段 capture（norm/target/maxgain）、字段数不符报坏命令。

**真机视觉实测**：开启归一化，逐家放不同音量的歌，确认波形填充一致；在此调 `target`/`max-gain`/`α`。

### 5.1 4.0 修订的测试计划（#67、#68）

每条先写成失败的测试，再改代码；每个新测试在隔离副本里注入所列缺陷确认变红，变异写法记进测试注释。数值界取自 §3.2 的原型结果，实施时以实测为准。

**归一化的起步与稳态（`audiocap/helper`，纯逻辑，Linux 可跑）**

除特别说明外按整帧（d = `hop`，25 帧每秒）喂入；「满幅」指输出 `rms ≥ 0.4`。

1. 验收序列，前导之后恒为 −20 dBFS：§3.2 第一张表的全部各行（前导为 0、−80、−50、−34、−26 dBFS 的单帧；3 帧渐入；8 帧 −60 dBFS；30 帧 −40 dBFS；比正常低 6、10、14 dB 的 8 帧与 20 帧；10 帧幅度线性渐入；每帧 +1、+2、+3、+6 dB 的渐入各若干帧）。断言：含前导在内没有一帧满幅，任何一帧高于目标不超过 3.02 dB，并逐行钉住回到 ±1 dB 的帧序号上界。缺陷：去掉下限（8 帧 −60 dBFS 之后 +9.5 dB）；下限不写回（30 帧 −40 dBFS 之后 +8.1 dB）；起步期系数用常数 α（首个正常帧 +15 dB）。
2. 验收序列，前导之后接合成节拍包络（落差 6、10、14 dB，多个起步相位）：与同一包络跑到稳态的参照逐帧比，「参照不满幅而被测满幅」的帧数为 0。前导取：无、1 帧 0、8 帧低 40 dB、30 帧低 20 dB、20 帧低 14 / 10 / 6 dB、20 帧每帧 +3 / +1 dB、10 帧每帧 +6 dB。缺陷：去掉重新起步（30 帧低 20 dB 时新增 3 / 6 / 11 帧）；重新起步后不重置 t。
3. 代价的上界，无前导接节拍包络：起步头 1.3 s 相对参照的平均偏差不低于 −1.0、−2.0、−2.7 dB（落差 6、10、14 dB），5 s 后逐帧在 ±1 dB 以内。缺陷：下限取本帧功率本身（输出恒不高于目标，估计跟随最响的帧）。
4. 前导为 1、25、100 帧的 0，或低于门限的帧，其后正常：首个正常帧的输出即目标（误差小于 0.01 dB）。缺陷：去掉门限；门限帧计入 t。
5. 无前导，电平分别为 −34、−20、−6 dBFS：首帧输出即目标。缺陷：以目标电平播种（−34 dBFS 时首帧低 19.9 dB）；把目标电平当一帧先验。
6. 起步期内 `ema_ms` 等于已计入各帧功率按样本数加权的平均：用相邻帧相差不超过 2 dB、不触发下限与重新起步的序列逐帧核对到起步期结束。缺陷：权重不是 `d/t`；起步期提前结束。
7. 起步期结束后与对称的指数平均逐帧一致：先喂满起步期，再分别喂 +10 dB、+20 dB 与 −10 dB 阶跃，每帧 `ema_ms` 等于参考递推 `ema += α·(ms − ema)`。缺陷：升降用不同系数；起步期不结束；下限或重新起步在起步期之后仍生效（+20 dB 阶跃即可分辨）。
8. 交接处不跳变：恒定输入下，起步期最后一帧与其后第一帧之间 `ema_ms` 不变；非恒定输入下变化不超过一帧的指数平均步长。缺陷：期满时重算或重新播种。
9. 重新起步的条件：本帧功率为估计的 10 倍略多时触发，略少时不触发（改由下限处理）；T 已满 τ 之后同样的跳变不触发。缺陷：比较方向写反；不限 T。
10. 重新起步至多把保护延长到 2τ：头 τ 秒内每隔 0.5 s 来一帧高 20 dB 的帧，累计 2τ 之后起步期必已结束（此后 +20 dB 的帧按指数平均处理）。缺陷：重新起步时把 T 清零。
11. 下限的取值：一帧 −26 dBFS 之后三帧 −20 dBFS，估计逐帧为两帧、三帧、四帧的平均，下限不介入；两帧 −27 dBFS 之后一帧 −20 dBFS，下限把估计抬到该帧功率的一半。缺陷：下限取 1/4（6 dB）或取本帧功率。
12. 门限的位置：−69.5 dBFS 的帧计入，−70.5 dBFS 的不计入（`rms` 是 float32，平方后取不到恰等于门限的值，含不含等号无从区分）。缺陷：比较方向写反；门限取 −60 或 −80 dBFS。
13. 已有估计之后的门限帧：`ema_ms`、t、T 不变，增益仍施加到该帧的 `rms`、`bins` 上。缺陷：门限帧不施增益；门限帧把估计清零。
14. 尚无帧计入时（首帧为门限帧或非有限值）：返回增益 1，`r` 逐位不变。缺陷：按 `ema_ms = 0` 算出 max-gain 施加。
15. `rms` 为 NaN、+Inf：不并入、不计入 t 与 T，其后的有限帧与跳过它们时结果相等（现有 `TestNormalizerIgnoresNonFiniteRMS` 改写）。
16. 起步期内增益封顶仍然生效：首帧 −65 dBFS（高于门限）时增益等于 max-gain。
17. 保活零帧经 `encodeFrame` 不动归一化的任何状态（现有 `TestEncodeFrameKeepaliveLeavesEMA` 改写，Windows-only）。
18. 关闭时逐位直通、状态不变（现有用例保留）。

**系数与时长（#68，同上）**

19. d = 1920、采样率 48000、τ = 1.3 s 时 `α = 0.030301`（误差 1e-6 以内）；d 趋于 0 时 α 趋于 0，不为负、不为 NaN。
20. 帧率 15、25、30、50、60 下（d 取各自的 `hop`），稳态 −20 dBFS 阶跃到 −10 dBFS 之后第 1、2、3 秒整的增益两两相差不超过 0.01 dB。缺陷：系数写死 0.03（第 1 秒处 60 帧每秒为 +0.68 dB，25 帧每秒为 +2.37 dB）。
21. 残帧按自己的时长取系数：同一段恒定输入，全部按 480 个样本的残帧喂与按整帧喂，相同累计时长处的 `ema_ms` 一致；15 与 25 帧每秒两路各喂同一组 480 样本的残帧，估计逐帧相等。缺陷：残帧用整帧的系数；起步期按帧数计。
22. 起步期按累计样本数结束：48000 Hz 下累计计入满 62400 个样本（1.3 s）才结束，差一个整帧（25 帧每秒下第 32 帧之后，61440 个）时仍在期内，重新起步与下限仍生效；残帧与整帧混合、各帧率下同样按样本数。另把「首帧 `rms` 0.001、次帧 0.1」写成用例，断言次帧不满幅。缺陷：期限与 τ 的秒数直接比（首帧的样本数即超过 1.3，起步期一帧结束，上述用例次帧输出约 1.14）；按帧数（如固定 33 帧）结束。
23. 默认配置的等价性：25 帧每秒、连续整帧，与现行算法的参考实现（写在测试内：首帧播种、系数 0.03）跑同一段合成节拍包络与 ±10 dB 阶跃，起步期过后 10 s 起逐帧输出相差不超过 0.05 dB（实测最大 0.048 dB，出在 −10 dB 下阶跃的尾段）。缺陷：τ 取错（取 1.0 s 时阶跃响应相差 0.3 dB 以上）。

**分帧（#68，纯逻辑，Linux 可跑）**

24. `hop = 1920`，喂 100 个 480 帧的包：恰出 25 帧，每帧窗口 1920 个样本，d = 1920。缺陷：按包数或按时间出帧。
25. `hop = 1600`，同样的 100 个包：恰出 30 帧，每帧 1600 个样本；用递增序列核对样本不丢、不重、不乱序。缺陷：到点才出帧而不切包（25 帧）；切包时丢掉后一段。
26. `hop = 400`，一个 480 帧的包跨两个帧界、一个 1200 帧的包含三帧：一次喂入出对应帧数。缺陷：每次喂入至多出一帧。
27. 包长不规则（1、479、481、4800 帧混合）：出帧数只取决于累计采样帧数。
28. 全为带静音标志的包：每 `hop` 出一帧保活零帧（窗口为空，d = 0）。缺陷：静音包不推进计数（退化为只靠墙钟）。
29. 一帧内半数为静音包：出真帧，窗口只含非静音样本，d 为非静音样本数。缺陷：d 恒报 `hop`。
30. 不满一帧不出帧；随后强制出帧：有残余为真帧（d 为残余样本数）、无残余为保活零帧，计数归零，之后重新凑满 `hop` 才出下一帧。缺陷：强制出帧后不清计数（下一帧提前）。
31. 峰值归属：把最大值放在跨界包的后一段，只进入后一帧的 `peak`。缺陷：整包的峰值都算给前一帧。
32. `hop < fftSize`（800）：连续有声时每帧交给分析的是最近 1024 个样本（递增序列核对），d 仍为 800；出过保活零帧后的下一帧不含旧样本；帧内混有静音包、或墙钟兜底出残帧时，交给分析的仍是最近 1024 个非静音样本。缺陷：不保留（每帧 800 个）；只保留 `fftSize − hop` 个（混有静音包的帧补不满分析窗）；保活后不清空；d 报成分析窗长度。
33. `hop ≥ fftSize`（含恰相等）：出帧后窗口清空，帧内混有静音包时也不带旧样本，交给分析的样本与现状相同。缺陷：恒保留 `fftSize` 个；判定含等号。
34. 空包、长度不足一个采样帧的包：不出帧、不死循环；单声道输入照常。
35. 帧率到 `hop` 的换算：25 → 1920，30 → 1600，60 → 800，15 → 3200，不能整除时向下取整。

**墙钟兜底（#68，Linux 可跑；循环级用假的读包函数与假时钟）**

36. 判定：读到数据时，距上次出帧不足 100 ms 不出帧、满 100 ms 出帧；没读到数据时，满一个帧间隔即出帧、不足不出。缺陷：读到数据时不检查；没读到数据时也用 100 ms。
37. 活性：`hop = 1920`，读包函数每 90 ms 返回一个 480 帧的非静音包、从不返回 0 帧：任意两帧的间隔不超过 190 ms（上限加一个包的到达间隔），出的是残帧。缺陷：只在返回 0 帧时检查（永不出帧）。
38. 完全没有数据：读包函数每 100 ms 返回 0 帧，每次返回都出一帧保活零帧。缺陷：兜底出帧后不更新上次出帧时刻；按样本数出帧后不更新（下一条）。
39. 连续流不受影响：读包函数每 10 ms 返回 480 帧，15、25、30、60 帧每秒下 1 s 内的帧数等于帧率，没有残帧。缺陷：上限低于帧间隔（15 帧每秒下切出残帧）；按样本数出帧后不更新上次出帧时刻。
40. 读包出错或停止信号：循环返回，不再出帧。

**真机项（由用户手动做，短跑；用 `tools/audioinspector/audio-inspector.html`）**

- 改后开启归一化复测四种捕获重启的情形：开头不再出现满幅块，至多略高于正常（不超过 3 dB）并在一两秒内回到正常；同一播放器内切歌、短暂停后恢复与改前观感相同。
- 可选，核实 §3.2「尚未核实」：改前的版本关闭归一化（`audio-normalize: false`），连 `/<player>/audio-ws`（根端点在切换播放器时看不到被预热那一路的开头），在捕获重启的情形下看走带开头与日志中「→ 真帧」一行的 `rms`（该行是空闲帧之后的第一帧，即这一路捕获的第一帧）。关闭归一化后开头不再有满幅块，且开头有一段明显低于其后的帧，推断即成立。
- 稳态：同一首歌改前改后的走带高度相同（默认配置下约占一半）。
- 帧率：`audio-frame-rate` 取 25、30、60 时检查页「帧率」读数与配置一致；暂停时静音帧仍在、空闲帧不混入；`/service-status` 与启动横幅显示配置值。
